# 宠物助手产品验收目录

这里维护 `dsh-codex-pet`、`dsh-session-assistant` 和 `dsh-realtime-voice` 的跨插件能力边界与验收用例。目标不是证明代码文件存在，而是证明用户可以从宠物入口完成讨论、整理草稿和明确交给主 Agent 的完整链路。

## 产品边界

| 组件 | 负责 | 明确不负责 |
| --- | --- | --- |
| `dsh-codex-pet` | 形象、动作、表情、气泡和助手状态呈现 | 回答问题、读取工作区、调用模型、执行 Agent 工具 |
| `dsh-session-assistant` | 会话入口、文本/语音讨论、上下文投影、草稿、显式提交、会话编排 | 直接编辑文件、运行终端、宣称任务已完成 |
| `dsh-realtime-voice` | Provider 中立的实时双工传输、音频事件、打断和工具往返 | 产品上下文、草稿规则、宠物渲染、凭据配置 |
| 主 Agent | 真正执行任务、使用工作区工具并返回可核验结果 | 被宠物或助手绕过用户确认静默调用 |

`suite.json` 是稳定用例目录；`runs/` 是按日期保存的真实结果。修改事件协议、上下文投影、助手工具、会话绑定、宠物入口、气泡、Realtime transport 或 Provider 时，必须更新受影响的 run，不能只改说明文档。

## 发布顺序

1. **G0 宠物身体**：独立渲染、动作、交互和降级稳定。
2. **G1 文本助手**：先完成问答、上下文、草稿、显式提交和新建会话。
3. **G2 宠物组合**：宠物只消费助手的中性状态、动作和可公开文本。
4. **G3 双工语音**：语音与文本共享同一套上下文、工具和权限语义。
5. **G4 真实端到端**：在 DSH GUI 和真实 Provider 上完成回归。

G1 未通过时不得以“语音已接宠物”作为发布结论。

## 证据等级

- `L1`：静态契约或纯函数单元测试。
- `L2`：跨模块/本地传输集成测试。
- `L3`：真实 DSH GUI，会话、工作区和生命周期证据。
- `L4`：真实 Realtime Provider 的音频、打断、延迟和失败恢复。

低等级证据不能替代用例声明的最低等级。`passed` 必须附可复核命令、日志、截图或 Session ID；没跑就是 `not-run`，环境缺失才是 `blocked`，已经确认缺功能则是 `failed`。

## 使用

```sh
npm run eval:check
```

首轮审计保存在 `runs/2026-08-21-baseline.json`。它是缺口基线，不是发布通过证明。
